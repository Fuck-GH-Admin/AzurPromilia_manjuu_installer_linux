# 接下来怎么做

当前 `info / install / verify / repair / preload / update` 的代码已经合并。官方 API、两种包类型的索引和小文件 CDN 探测通过，但完整游戏安装、全量校验和真实版本更新还没有验收。

接下来只做两件事。先把下载器本身补可靠，再用真实官方资源跑通安装和版本管理。不做复杂的项目管理，也不为了文档而拆阶段。

## 第一步：把下载器做可靠

集中处理会影响完整下载和文件安全的问题：

- 下载任务遇到首个严重错误后及时取消，不让其他 worker 继续无意义地消耗流量；保留断点续传能力。
- 下载前检查磁盘空间，分别考虑逐文件下载、分片下载与解压、预下载和更新。
- ZIP 解压增加总解压大小检查，并继续保留路径穿越、重复路径、符号链接等保护。
- 补上 install、repair、preload、update 的关键流程回归测试：版本标记不能提前写入；排除文件和未知文件不能误删；失败后重跑能继续。
- 跑通 CI：Go race tests、vet、Linux amd64/arm64 构建。

这些本地测试只证明程序自己的逻辑，不代替真实官方服务器验证。

## 第二步：用真实服务器跑通完整链路

1. 重新执行 `info`，确认当前 released 版本、`downloadMode`、实际包类型，以及服务器是否提供不同版本的 preload。
2. 在独立测试目录执行 `install`，按官方 `downloadMode` 自动选择 REALITY 或 SLICE。
3. 完成全量校验：REALITY 检查全部文件 MD5；SLICE 检查全部分片、合并 ZIP 的 MD5，以及解压文件的 CRC32/大小。
4. 在可丢弃的测试目录验证 `repair`，确认损坏文件能恢复。
5. 只有官方确实提供不同的 preload/新版本时，再验证 `preload` 和 `update`，检查差异下载、缓存复用、旧文件清理和最终校验。

如果官方暂时没有 preload 或新版本，就记录当前条件不足，不伪造版本、不搭模拟服务器来冒充实服结果。全量安装也不会直接对用户现有游戏目录做首次试验。

测试结果直接更新现有的 `IMPLEMENTATION_STATUS.md` 和 `LOCAL_TESTING.md`，不再额外维护一套复杂的验收台账。

## 暂时不做

游戏启动、Proton 配置、GUI 和桌面集成先放一边。当前目标是让下载、安装、校验、修复和更新可靠；等确实需要管理游戏启动时再回来做，不为此提前维护单独阶段。

## 当前已知基线

- 官方匿名 packageconfig 曾成功返回 `code=0`，记录版本为 `1.0.0.30`。
- REALITY 索引实测解析出 40,457 个文件、29 个目录；SLICE 索引解析出 752 个分片。
- 两种包类型均完成官方 CDN 小文件大小和 MD5 校验；主、备用 CDN 均有探测记录。
- 真实 CDN Range 续传返回 HTTP 206，续传文件校验通过。
- 以上都不是全量安装成功的证据。当前 `downloadMode` 和 preload 状态需要重新执行 `info` 确认。
